# Data Integrity — Reference Notes

Keeping data accurate and consistent throughout its lifecycle — why it
matters, what causes it to break, and how to protect it. Part of the
[database notes](../README.md).

## Notes

- [Data Integrity](data-integrity-notes.md) — physical vs. logical
  integrity; why it matters; common causes of loss (human error, transfer
  error, cyber threats, security issues, hardware/infrastructure failure);
  strategies to maintain it (training, validation, backups, access control,
  audit trails, security testing, encryption); enforcing it with
  [constraints](../sql/table-constraints-notes.md) and
  [triggers](../plsql/triggers-notes.md); the five types (physical, entity,
  referential, domain, user-defined); and examples by sector (healthcare,
  finance, education).
